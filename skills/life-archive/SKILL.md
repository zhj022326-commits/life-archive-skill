# 人生档案

维护用户可编辑的 Markdown 人生档案。只响应用户明确发起的归档或访谈；日常聊天中不主动提取、写入或启动访谈。

## 入口识别与默认行为

- 用户通过 `/life-archive`、技能列表中的“调用/使用”按钮、`$life-archive` 或明确同义方式显式调用本 Skill，且没有附加参数时，默认执行“归档本次对话”。不能因为参数为空而只介绍 Skill 或询问用户要做什么。
- 显式调用并附带“访谈”“开始人生访谈”等参数时，执行访谈流程。
- 用户在普通聊天中只是谈论个人经历，或仅在文字里提到 Skill 名称，不视为显式调用，不自动归档。
- 用户请求查看、修改或删除档案时，只执行其明确要求的操作，并遵守下文的文件规则。

## 档案位置

首用时必须先解决档案位置：检查当前上下文是否已经明确指定位置，以及当前工作区内是否存在可识别的人生档案。如果没有已知位置，在首次显式调用时先用一句话说明要设置存储位置，再询问用户希望存在哪里；在用户回答前不创建、不写入，然后继续当前默认操作。用户给出盘符时，直接在该盘根目录创建名为 `人生档案` 的目录（例如“D 盘”对应 `D:\人生档案`）；用户给出具体文件夹路径时，直接将该路径作为档案目录。不得再追问是否创建，也不得改选其他路径。之后将确认的位置写入档案目录索引，并在后续调用中沿用。不能假设不同智能体共享文件。

用户给出保存位置后，若目录不存在，直接创建并复制本 Skill 附带的基础模板。若目录已经存在，检查现有内容，只补充缺少的标准模板；不覆盖、重置或删除任何已有文件。只创建必要文件。若环境不能读写该位置，清楚说明限制，不要声称已保存，也不要擅自改存其他位置。

只读取本次任务需要的文件：先读 `目录.md`，再读相关主题文件；访谈体检时读取档案内全部现存文档。以实际文件为准，目录过期时修正它。尊重用户手工编辑的标题、格式和内容，不重置文件。

## 归档流程

1. 只使用当前实际可访问的对话上下文；不声称读取或归档其他会话、被截断内容或无法访问的历史。
2. 提取未来理解用户有价值的信息。判断是否属于用户本人，并区分事实、经历、当前状态、计划、偏好、临时感受和假设。
3. 排除普通闲聊、第三人称经历、假设例子、无关知识内容和 AI 自行生成的分析。不得把推断写成用户事实；不确定内容保留限定语，通常放入“待核实信息”。
4. 对照相关档案，选择新增、补充、合并、更新、标记待核实或舍弃。语义相同的信息更新原条目，不重复堆叠。
5. 新状态明确取代旧状态时，将新内容标为当前；只有有长期意义时才保留简短历史。无法判断是状态变化还是矛盾时，不擅自裁定，标记待核实。
6. 明确纠正优先于旧记录。对重要内容作实质性改写或删除前，先在同目录保存一份带日期的 `.bak-YYYY-MM-DD` 副本；小幅补充不备份。备份仅用于恢复，不是第二份真源。
7. 新建、删除或重命名文档时更新 `目录.md`；正文更新仅在主题概述变化时同步目录。
8. 简短报告保存了哪些类别；若没有有价值的新信息，说明档案未改动。若可读上下文有限，简短注明范围。

## 访谈流程

访谈仅在用户主动启动后进行。启动后先读取档案并展示一次简洁的体检报告，至少包含：主要领域的资料覆盖程度（较完整/一般/不足/不适用/用户暂不记录）、已知矛盾或模糊信息是否存在、优先补充方向，以及可选方向。覆盖程度只描述档案现有资料，不评价用户人生，不根据常见人生模板假设用户必须提供某类信息；不使用百分比。

报告后让用户选择：补充缺失资料、澄清矛盾/模糊信息、综合访谈，或指定某个领域。用户已经在启动语中指定方向时，直接采用该方向，不重复询问。

访谈中每轮只问一个高价值问题；依据回答追问，不重复已明确内容。允许跳过、结束或改方向。不要诱导用户接受 AI 的猜测。对于重要或含糊回答，先简短复述理解并确认；已确认的信息及时写入相关文件，不等待整场结束。结束时简短说明新增/澄清的内容及尚待确认项。一次访谈启动只显示一次体检报告。
